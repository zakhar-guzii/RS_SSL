❯ but why not statified group split?                                            

⏺ You're right — StratifiedGroupKFold is strictly better here because it also
  preserves class distribution across splits, not just subject grouping.
  GroupShuffleSplit randomly assigns subjects without any class balance
  guarantee, so a split could end up with very few "downstairs" samples in test
  just by chance. StratifiedGroupKFold tries to balance both simultaneously.

  The only trade-off is that it's fold-based so test_size ≈ 1/n_splits rather
  than an exact ratio — but we can round n_splits = round(1/test_ratio) to get
  close. Let me fix it.

❯ in the merged dataset, how does "subject" look like and what does it          
  represent                                                                     

⏺ From the notebook's merge cell, each entry is a string
  "{source}_{original_id}". For example:

  - "uci_1", "uci_2", ... "uci_30" — 30 subjects
  - "wisdm_1", "wisdm_2", ... "wisdm_36" — 36 subjects
  - "motionsense_1", ... "motionsense_24" — 24 subjects
  - "hhar_a", "hhar_b", ... "hhar_i" — 9 subjects (HHAR uses letter IDs)

  So subject is a 1-D string array of length n_windows (61 891 entries), where
  each value identifies which person produced that window. The source prefix is
  there to avoid collisions — subject "1" appears in all four datasets but
  they're different people, so "uci_1" vs "wisdm_1" keeps them distinct.

  This is exactly what gets passed as groups=subjects to StratifiedGroupKFold:
  it sees 99 unique group labels and ensures every window belonging to a given
  person lands entirely in one split.
